# 문제 정의와 공정 비교 규칙

## 연구 질문

메카트로닉스프로젝트의 Search 수업에서 UCS와 A*의 탐색 영역 차이를 본 것이 출발점이다. 여기서는 별도의 가중치 격자에서 **목표 정보를 쓰는 A***와 **양쪽에서 출발하는 양방향 Dijkstra**가 어떤 지도 구조와 출발–목표 거리에서 유리한지 직접 측정한다. 단방향 Dijkstra는 기준선이다. 세 방법은 모두 동일한 최적 경로 문제를 푼다.

## 입력 그래프

- 지도는 높이 `H`, 너비 `W`의 직사각형 2차원 격자다.
- 이동은 상·우·하·좌 네 방향으로만 가능하다. 대각선 이동과 격자 밖 이동은 없다.
- 통과 가능한 칸의 비용은 정수 1~9다. 벽은 `None`으로 표시하고 통과하지 않는다.
- 인접한 두 통과 가능 칸 `u→v`의 비용은 **도착 칸 `v`의 비용**이다. 따라서 역방향 탐색에서는 원래 간선 `u→v`의 비용 `cost(v)`를 그대로 사용해야 한다.
- 출발점 `S`와 목표점 `G`는 통과 가능한 칸이다. 위치는 `(행, 열)`로 표시한다. 출발점 자체에는 비용을 부과하지 않는다. `S=G`이면 최적 비용은 0이다.
- 도달할 수 없는 지도는 테스트 대상이지만 핵심 성능 실험은 도달 가능한 사례로 구성한다.

## 결과 규약

- 도달 가능하면 `reached=True`, 비용은 0 이상의 정수, 경로는 `S`에서 시작해 `G`에서 끝나는 인접 칸 목록이다. 경로를 따라 합산한 진입 비용은 반환 비용과 같아야 한다.
- 도달 불가능하면 `reached=False`, 비용은 `None`, 경로는 빈 목록이다.
- 확장 정점 수는 유효한 최소 거리 항목을 우선순위 큐에서 꺼내 이웃 완화를 시도한 정점 수다. 목표점에서 종료하면 목표점은 확장 수에 포함하지 않는다. 오래된 큐 항목은 세지 않는다. 양방향은 정·역방향 수를 합산한다.
- 우선순위 큐 삽입·제거 횟수는 중복·오래된 항목을 포함해 별도 기록할 수 있다.

## 알고리즘과 공정성

1. 단방향 Dijkstra: 우선순위는 출발점에서의 확정 전 거리 `g`. 같은 `g`이면 `(행, 열)`이 작은 정점을 먼저 꺼내며, 같은 비용의 다른 경로는 부모를 변경하지 않는다.
2. A*: 우선순위는 `g+h`. `h`는 목표까지의 맨해튼 거리에 지도에서 통과 가능한 칸의 최소 진입 비용을 곱한 값이다. 이 값은 남은 실제 비용을 넘지 않는다.
3. 양방향 Dijkstra: 원래 그래프와 역방향 그래프에서 동시에 탐색한다. 첫 접촉으로 종료하지 않고 최선 연결 비용 `μ`와 양쪽 유효 최소 큐 키를 비교해 종료한다. 경로는 원래 방향으로 복원한다.

세 방식은 동일한 지도·출발/목표·Python 실행 환경을 사용한다. A*와 양방향 탐색의 동점 처리 및 방향 선택 정책은 각 구현 단계에서 명시하고 모든 사례에서 고정한다. 지도 생성·파일 입출력·그림 생성 시간은 탐색 시간에서 제외한다. 각 단계에서 비용과 경로를 확인하며, 작은 지도에는 독립적인 Bellman–Ford 기준을 쓴다.

## 측정과 분석 범위

- 핵심 지표: 탐색 실행 시간과 확장 정점 수. 최적 비용/경로 일치는 성능 지표가 아니라 필수 정확성 검사다.
- 핵심 실험: 101×101, 열린 지도·장벽 지도·미로형 지도, 가까운/먼 목표, 조합당 독립 시드 12개로 **72개 사례**다. 방식별 워밍업 후 3회 시간을 잰다.
- 크기 보조 실험: 열린 지도와 장벽 지도, 먼 목표, 사전 고정한 시드 6개씩에 대해 51×51·101×101·201×201을 비교한다. 101×101 결과는 핵심 실험에서 재사용하고 추가 사례는 24개다.
- 같은 사례에서 세 방식의 시간과 확장 수를 짝지어 비교한다. 지도 유형·거리별 중앙값과 분포, 대표 사례와 반례를 제시한다. 작은 크기 표본으로 일반적인 시간 복잡도 법칙을 입증했다고 주장하지 않는다.
- 지도 생성 규칙, 시드, 측정 반복, 결측 처리, 분석 기준은 본 실험 전에 고정한다. 버그 수정 뒤에는 이전 원시 CSV를 덮어쓰지 않고 새 버전으로 실행한다.

## 중간발표 이후의 범위 조정

중간발표는 다양한 지도·가중치·크기·휴리스틱·정책·공개 벤치마크와 많은 시간 반복을 탐색 가능한 후보로 제시했다. 최종 실행 계획에서는 같은 세 알고리즘과 핵심 연구 질문을 유지하면서, 검증 가능한 사례 72개와 작은 크기 보조 실험으로 범위를 제한했다. 실행한 조건만 결과로 보고하고, 수행하지 않은 발표 당시 후보를 실행한 것처럼 쓰지 않는다. 범위 조정의 이유는 정확성 테스트, 원시 데이터 보존, 이론과 연결한 해석, 제3자 재현에 시간을 집중하기 위해서다.
