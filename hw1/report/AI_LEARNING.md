# 힙 정렬 AI 학습 자료
2022193003 김형균

## 1. 힙은 정렬된 배열인가?
아니다. 최대 힙은 부모의 key가 자식의 key 이상인 완전 이진 트리다.
형제 사이의 대소관계나 배열 전체의 오름차순을 보장하지 않는다.
0부터 시작하는 배열에서 부모 i의 자식은 2i+1, 2i+2이고 최대값은 0번에 있다.

## 2. 어떻게 오름차순 정렬하는가?
마지막 내부 노드 n/2-1부터 0까지 siftDown하여 최대 힙을 만든다.
루트의 최대값을 활성 구간 마지막 원소와 교환하고 활성 크기를 하나 줄인다.
루트부터 더 큰 자식과 비교·교환하며 힙 조건을 복구한다. 이를 반복하면
오른쪽의 정렬 완료 구간이 점점 커진다. siftDown은 자식 서브트리가 이미
힙이라는 전제에서만 현재 루트를 복구한다.

## 3. 작은 예시
입력 [4,1,3,2] → 힙 [4,2,3,1].
4를 끝에 놓고 복구: [3,2,1 | 4].
3을 끝에 놓고 복구: [2,1 | 3,4].
2를 끝에 놓으면 [1 | 2,3,4]. 세로선 오른쪽은 정렬이 끝난 구간이다.

## 4. 왜 힙 만들기는 O(n)인가?
모든 노드가 트리 높이 전체를 내려가는 것은 아니다. 절반가량은 잎이고,
높이 h인 노드 수는 대략 n/2^(h+1)이다. 높이별 비용을 더하면
n * sum(h/2^(h+1)) = O(n)이다. 반면 최대값을 꺼내는 단계는 최대 n-1회,
한 번의 복구는 O(log n)이므로 전체 최악 시간은 O(n log n)이다.

## 5. 안정 정렬인가?
아니다. 이 구현에서 [(1,A),(1,B)]를 힙 정렬하면 마지막 루트 교환으로
[(1,B),(1,A)]가 된다. 같은 key의 원래 순서가 바뀌므로 불안정 정렬이다.

## 6. 추가 공간은?
이 구현의 siftDown은 반복문을 쓰므로 재귀 스택이 없다. 교환용 Record 하나와
상수 개의 인덱스만 필요하다. 따라서 전체 보조 공간은 O(1)이다.
보고서의 buffer_bytes는 명시적 원소 저장 공간만 세며 인덱스, 포인터,
함수 호출 프레임, 할당기 내부 정보는 정확한 바이트 측정에 포함하지 않는다.

## 7. 항상 병합 정렬보다 빠른가?
아니다. 두 정렬의 최악 시간 차수는 같지만 실제 연산 수와 접근 패턴은 다르므로
속도 우열은 직접 측정한다.
